\section{Objective}
To classify emails as spam or ham (non-spam) using two supervised classification
paradigms -- Logistic Regression (a probabilistic linear classifier) and Support
Vector Machines (a margin-based classifier with linear and non-linear kernels) --
and to systematically analyze the effect of hyperparameter tuning (regularization
strength, kernel choice, penalty type, and kernel coefficient) on classification
performance using the Spambase dataset.

\section{Problem Statement}
Given a set of 57 numerical features extracted from the content of an email
(word frequencies, character frequencies, and statistics on runs of capital
letters), the task is to predict a binary label indicating whether the email is
\emph{spam} (1) or \emph{ham} (0). The input is a feature vector
$x \in \mathbb{R}^{57}$ for each email, and the output is a class label
$y \in \{0,1\}$. The objective is to build classifiers that generalize well to
unseen emails, minimizing both false positives (legitimate mail marked as spam)
and false negatives (spam reaching the inbox), and to compare a linear
probabilistic model against margin-based kernel models under systematic
hyperparameter tuning.

\section{Data Preprocessing}
\begin{itemize}
\item \textbf{Missing value handling:} The 25 missing cells (spread across 21
features) were imputed using the median of each respective column, chosen for
robustness against the heavy right-skew of word-frequency features.
\item \textbf{Encoding:} Not required -- all 57 input features are already
continuous numerical values, and the target is a binary integer label.
\item \textbf{Feature scaling:} All 57 features were standardized using
\texttt{StandardScaler} (zero mean, unit variance), fitted on the training set
only and applied to the test set, since both Logistic Regression's gradient-based
solvers and SVM's margin/kernel computations are sensitive to feature scale.
\item \textbf{Train-test split:} An 80/20 stratified split was used
(\texttt{train\_test\_split} with \texttt{stratify=y}), producing 3680 training
and 921 test samples, preserving the $\approx$61/39 class ratio in both sets.
\item \textbf{Feature engineering:} Not performed -- the 57 provided features
(word frequencies, character frequencies, capital-run-length statistics) were
used as-is, consistent with the standard Spambase benchmark setup.
\end{itemize}

\section{Machine Learning Algorithm}

\subsection*{Logistic Regression}
\textbf{Working principle:} Logistic Regression models the probability that an
email is spam using a linear combination of features passed through a sigmoid
function:
\[
P(y=1\mid x) = \frac{1}{1 + e^{-(w^Tx + b)}}
\]
A decision threshold of 0.5 is applied to convert the predicted probability into
a class label. The weights $w$ are learned by minimizing the log-loss
(cross-entropy) objective, optionally with an L1 or L2 penalty term.

\textbf{Mathematical formulation:} For $n$ training samples, the regularized
objective minimized is
\[
J(w) = -\frac{1}{n}\sum_{i=1}^{n}\Big[y_i\log(\hat{p}_i) + (1-y_i)\log(1-\hat{p}_i)\Big] + \frac{1}{C}\,R(w)
\]
where $\hat{p}_i = \sigma(w^Tx_i+b)$, $C$ is the inverse regularization strength,
and $R(w) = \|w\|_1$ (L1) or $\|w\|_2^2$ (L2).

\textbf{Advantages:} Fast to train, highly interpretable coefficients, produces
well-calibrated probabilities, works well when classes are close to linearly
separable, and L1 regularization enables automatic feature selection.

\textbf{Limitations:} Assumes a linear decision boundary in feature space
(cannot capture complex non-linear interactions without manual feature
engineering), and is more sensitive to outliers and multicollinearity than
margin-based or tree-based methods.

\subsection*{Support Vector Machine (SVM)}
\textbf{Working principle:} SVM finds the hyperplane that maximizes the margin
between the two classes, using only the closest points (support vectors) to
define the decision boundary. For non-linearly separable data, a kernel
function implicitly maps inputs into a higher-dimensional space where a linear
separator can be found.

\textbf{Mathematical formulation:} SVM solves
\[
\min_{w,b}\ \frac{1}{2}\|w\|^2 + C\sum_{i=1}^n \xi_i \quad \text{s.t. } y_i(w^T\phi(x_i)+b)\geq 1-\xi_i,\ \xi_i\geq 0
\]
where $\phi(\cdot)$ is the (implicit) kernel feature map. The kernel trick
allows this to be computed via a kernel function $K(x_i,x_j)=\phi(x_i)^T\phi(x_j)$
without explicitly computing $\phi$. Kernels evaluated: Linear
$K(x_i,x_j)=x_i^Tx_j$, Polynomial $K(x_i,x_j)=(\gamma x_i^Tx_j + r)^d$, RBF
$K(x_i,x_j)=\exp(-\gamma\|x_i-x_j\|^2)$, and Sigmoid
$K(x_i,x_j)=\tanh(\gamma x_i^Tx_j + r)$.

\textbf{Advantages:} Effective in high-dimensional spaces, robust to
overfitting when the margin is well-regularized, and the kernel trick allows
flexible non-linear decision boundaries without explicit feature transformation.

\textbf{Limitations:} Computationally expensive to train on large datasets
(training time grows super-linearly with sample count, as observed in Table~9),
sensitive to the choice of kernel and its hyperparameters ($C$, $\gamma$,
degree), and less directly interpretable than Logistic Regression.

\section{Discussion}
Both classifiers achieved strong and closely matched performance on this task,
with tuned SVM (RBF kernel) slightly edging out tuned Logistic Regression on
accuracy (0.9273 vs 0.9218) and F1-score (0.9086 vs 0.9016), while Logistic
Regression retained a marginal edge in ROC-AUC (0.9610 vs 0.9599) and was
substantially faster to train and tune. The closeness of the results across
both models, and the strong performance of the Linear SVM kernel specifically,
indicates that spam/ham separation in this feature space is close to linear,
with only a small amount of additional benefit available from the non-linear
RBF mapping. Hyperparameter tuning had a visible but modest effect for
Logistic Regression: a small $C=0.01$ (strong L2 regularization) was preferred
over the default, indicating the baseline model was mildly overfitting on the
57-dimensional standardized feature space. For SVM, the choice of kernel had a
much larger effect than the choice of $C$ or $\gamma$ within a kernel, with the
Polynomial kernel underperforming the other three by 5-6 percentage points of
accuracy. A limitation of this study is that the SVM grid search was performed
on a stratified subsample (1200 points) for computational tractability, which
could slightly under- or over-estimate the true optimum compared to searching
on the full 3680-sample training set; the reported test-set metrics, however,
are from the best model refit on the full training data. Future improvements
could include probability calibration, cost-sensitive thresholding to reduce
false negatives, and ensembling the two models to combine SVM's slightly higher
raw accuracy with Logistic Regression's better-calibrated probabilities.

\section{Conclusion}
This experiment implemented and compared Logistic Regression and Support
Vector Machine classifiers for spam email detection on the Spambase dataset,
with systematic hyperparameter tuning via grid search and 5-fold
cross-validation. The tuned SVM with an RBF kernel achieved the best overall
test accuracy (92.7\%) and F1-score (0.909), narrowly outperforming tuned
Logistic Regression (92.2\% accuracy, F1 = 0.902), while Logistic Regression
offered comparable discriminative power (ROC-AUC $\approx$0.96 for both),
much faster training, and substantially better interpretability through its
feature coefficients. The results confirm that character-frequency features
(especially \texttt{!} and \texttt{\$}) and capital-run-length statistics are
the strongest indicators of spam, and that regularization and kernel choice
are the most impactful hyperparameters for this problem. Given the near-equal
performance and Logistic Regression's speed and interpretability advantages,
it would be the preferred choice for a production spam filter unless SVM's
small accuracy gain is critical to the deployment.
